# 一键生成竞赛项目书工作流草案

## 目标

输入项目主题、参考文档、附件和竞赛类型后，先理解当前项目，再生成符合大创、挑战杯、互联网+等场景的项目书。

## 总原则

1. 先理解当前项目，再写正文。
2. 有参考文档时，只学结构、段落节奏、表格格式和写法，不学别的项目事实。
3. 没有参考文档时，走竞赛书结构，不借历史样例。
4. 不允许固定 4 人团队、固定 16 周、固定 A1-A11 之类的隐藏默认值。
5. Claude 审计要贯穿计划、代码、初稿和定稿。

## 工作流节点

### 1. 项目理解闸门

- 输入：项目名、简介、附件、竞赛类型
- 输出：一句话定义、目标用户、场景、痛点、方案、证据、缺失信息、研究问题
- 规则：不清楚就停止，不进入正文

### 2. 参考文档学习

- 输入：用户上传的参考文档
- 输出：结构蓝图、标题层级、段落节奏、表格密度、排版习惯
- 规则：只学写法，不学事实

### 3. 当前主题检索

- 输入：当前项目主题、竞赛类型
- 输出：政策、行业数据、研究现状、竞品信息、事实来源
- 规则：只检索当前题目，不跨项目

### 4. 竞赛骨架生成

- 输入：项目理解结果、参考写法、竞赛类型
- 输出：目录、章节顺序、附件清单、图表清单、预算框架
- 规则：骨架必须匹配竞赛类型，而不是通用模板

### 5. 分章写作

- 输入：骨架、证据、主题资料
- 输出：逐章正文
- 规则：一章一章写，章节之间共享理解闸门结果

### 6. 图表与流程图生成

- 输入：章节内容
- 输出：技术路线图、流程图、竞品表、预算表、附件索引
- 规则：图表必须能回指正文中的具体论断

### 7. Claude 审计循环

- 输入：计划、代码、理解报告、初稿
- 输出：返修意见、缺陷列表、通过/打回结论
- 规则：不通过就回到写作或理解闸门

### 8. 排版导出

- 输入：定稿正文、图表、附件
- 输出：Word / PDF
- 规则：字体、字号、表格、分页、页码统一

## 推荐技能拆分

1. `project-intake-gate`
2. `reference-project-book-replica`
3. `challenge-cup-project-book`
4. `project-book-audit-loop`

## 适配策略

- 大创：强调创新性、可行性、团队、预算和实施计划。
- 挑战杯：强调学术性、问题意识、方法严谨性和证据链。
- 互联网+：强调商业模式、市场、落地性和增长路径。

## 需要写进实现层的硬约束

- 不从其他项目目录读取事实。
- 不从历史样例继承项目名、团队、预算、附件和技术路线。
- 有参考文档时，只做结构迁移。
- 无参考文档时，只用当前主题和竞赛规则生成。
- 审计结果必须能打回到上一层，不只是展示给用户看。
